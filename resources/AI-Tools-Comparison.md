# AI Tools Guide for B.Sc. Computer Science Students

Tool names, available features, account requirements, data policies, and free
usage limits change frequently. Verify current details before class; do not
promise that a product or feature is free or available to every student. Use
only tools approved by the college.

## Select a Tool by Task

| Tool type | Useful for | What to verify |
|---|---|---|
| General-purpose AI chat assistant (for example, ChatGPT, Gemini, or Claude) | Explanations, brainstorming, drafts, code discussion | May make up facts or code; check sources, run tests, and review data settings |
| IDE coding assistant | Code completion, explanation, test suggestions, refactoring | Review every change, understand the code, run tests, and follow course rules |
| Web/search-grounded assistant | Finding current information and starting research | Open and evaluate the cited source; a citation does not guarantee support |
| Document-grounded workspace (for example, NotebookLM) | Q&A and study notes grounded in selected documents | Check cited passages and source quality; it is not automatically a custom, deployable chatbot |
| Notebook environment (for example, Google Colab or local Jupyter) | Running small code experiments and demonstrations | Check account access, runtime limits, shared-data risks, and code safety |
| Automation platform (for example, Make, Zapier, or n8n) | Connecting a trigger to predefined actions | Free limits, integrations, permissions, and institutional approval vary |

## Choosing an Assistant for a CS Task

1. **Explaining a concept:** Ask for a definition, small example, and
   misconception; compare with course notes.
2. **Debugging:** Share the smallest non-sensitive example, expected behavior,
   actual behavior, and error. Ask for hypotheses and tests; run the code.
3. **Research:** Ask for source links, then inspect the sources directly.
4. **Document Q&A:** Use approved sources and verify that each answer is
   supported by the cited text.
5. **Automation:** Start with a diagram or synthetic data; do not connect
   personal accounts or real student records in a class exercise.

## Safe and Responsible Use

- Never paste passwords, API keys, personal records, confidential code, or
  unpublished institutional material into an unapproved service.
- Follow course and college rules for AI assistance and disclosure.
- Do not submit generated code you cannot explain.
- Test generated code in a safe environment; do not run unknown commands
  blindly.
- Treat plan names, pricing, model names, and feature availability as
  changeable; check each provider's current product information.

## Workshop Tool Checklist

Before the workshop, the instructor should:

- Confirm which tools students may use and what account requirements apply.
- Prepare an approved sample CS handout and synthetic test data.
- Prepare a backup demonstration in case a service is unavailable.
- Avoid requiring personal accounts, payment details, API keys, or a specific
  provider for assessment.
