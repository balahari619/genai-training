# Assessment Rubric & Evaluation Guide

**For instructors to assess student work and learning**

---

## 📊 Overall Workshop Assessment Structure

```
Total Marks: 100

Day 1 & 2 Activities:        20 marks
Project 1 (CS Course Assistant): 30 marks
Project 2 (CS Career Assistant): 40 marks
Final Participation/Demo:      10 marks
────────────────────────────────
TOTAL:                        100 marks
```

---

## 📋 Detailed Rubrics

### 1. DAY 1 & 2 ACTIVITIES (20 Marks)

**Evaluating:** Participation in activities, prompt quality, practical learning

#### Participation in Activities (10 marks)

| Score | Criteria |
|-------|----------|
| **9-10** | Actively participated in all activities, completed all exercises, engaged thoughtfully |
| **7-8** | Participated in most activities, completed most exercises, showed engagement |
| **5-6** | Participated in some activities, completed some exercises, moderate engagement |
| **3-4** | Minimal participation, completed few exercises, low engagement |
| **0-2** | Did not participate or complete activities |

**What to Look For:**
- ✅ Student completed all 5+ activities
- ✅ Asked questions, tried things independently
- ✅ Engaged with peers during activities
- ✅ Showed willingness to experiment

---

#### Prompt Quality (10 marks)

| Score | Criteria |
|-------|----------|
| **9-10** | Prompts are specific, clear, include role/context/instructions; student shows understanding of prompt engineering principles |
| **7-8** | Prompts are mostly well-structured; student shows good understanding of most principles |
| **5-6** | Prompts are somewhat clear but lack some key elements (role, context, or format); basic understanding shown |
| **3-4** | Prompts are vague or missing multiple elements; limited understanding |
| **0-2** | Prompts are very vague or no meaningful prompts written |

**Prompt Evaluation Checklist:**
- [ ] Includes a defined role/persona?
- [ ] Provides context (who it's for, what situation)?
- [ ] Has specific instructions (not vague)?
- [ ] Specifies output format?
- [ ] Includes constraints (length, tone, etc)?

**Example Good Prompt (9-10 marks):**
```
"Act as a CS tutor. Explain recursion to a first-year B.Sc. Computer Science
student. Include a small example, identify the base case, and ask two
questions that check understanding. Keep the explanation under 200 words."
```

**Example Poor Prompt (2-3 marks):**
```
"Explain recursion."
```

### 2. PROJECT 1: CS COURSE KNOWLEDGE ASSISTANT (30 Marks)

**Evaluating:** Quality of approved CS sources, grounding checks, documentation, and demonstration

#### Source Selection (8 marks)

| Score | Criteria |
|-------|----------|
| **7-8** | Selected 3-4 relevant, current, permitted sources for one focused CS topic |
| **5-6** | Selected 2-3 suitable sources with mostly clear scope |
| **3-4** | Sources are loosely related, dated, or insufficiently described |
| **0-2** | Sources are missing, unsuitable, or used without permission |

**Checklist:**
- [ ] Sources address a defined CS topic?
- [ ] Sources are readable, current, and allowed for use?
- [ ] Source titles and dates are recorded?
- [ ] Personal or confidential information is excluded?

---

#### Assistant Functionality (10 marks)

| Score | Criteria |
|-------|----------|
| **9-10** | Workspace answers a range of questions; student checks citations and identifies unsupported claims and limits |
| **7-8** | Most tested answers are source-supported; minor gaps in evaluation |
| **5-6** | Some answers are useful, but checking or scope testing is inconsistent |
| **3-4** | Little evidence of source verification or meaningful testing |
| **0-2** | No working demonstration or student treats unsupported output as fact |

**Functionality Checklist:**
- [ ] Successfully set up a document-grounded workspace?
- [ ] Sources uploaded and processed?
- [ ] Tested direct, synthesis, and out-of-scope questions?
- [ ] Checked cited passages against original sources?
- [ ] Clearly states that a workspace is not automatically a custom, deployable chatbot?

**Test Questions Should Cover:**
- Definitions and examples from selected CS course material
- Compare or synthesize information across sources
- Technical questions requiring independent verification
- Edge cases (not in documents)

---

#### Documentation (7 marks)

| Score | Criteria |
|-------|----------|
| **6-7** | Clear, thorough documentation; explains purpose, documents used, capabilities, limitations, improvements |
| **4-5** | Good documentation; covers most aspects; mostly clear |
| **2-3** | Basic documentation; missing some key elements; some clarity issues |
| **0-1** | Minimal or unclear documentation |

**Documentation Should Include:**
- [ ] Purpose and problem it solves
- [ ] List of documents uploaded
- [ ] Sample conversations/screenshots
- [ ] Strengths (what it does well)
- [ ] Limitations (what it can't do)
- [ ] Potential improvements
- [ ] How others could use this

---

#### Demonstration (5 marks)

| Score | Criteria |
|-------|----------|
| **4-5** | Clear, smooth demo; answers 2-3 questions well; explains how it works; handles questions confidently |
| **3** | Demo works; shows functionality; minor awkwardness; mostly explains well |
| **2** | Demo has some issues; partially shows functionality; unclear explanation |
| **0-1** | Demo doesn't work or can't explain |

**Demo Evaluation:**
- [ ] Demo is 5 minutes or less?
- [ ] Shows system working (asks questions, gets answers)?
- [ ] Explains how it works?
- [ ] Handles tech issues gracefully?
- [ ] Answers audience questions?
- [ ] Shows confidence in understanding?

---

### 3. DAY 4 WORKFLOW CHALLENGE (Optional, Ungraded)

Students may sketch or prototype a workflow using synthetic data. This is
practice, not a required project or graded deliverable. Do not require personal
accounts, paid services, API keys, or live student records.

### 4. PROJECT 2: CS CAREER AND TECHNICAL INTERVIEW ASSISTANT (40 Marks)

**Evaluating:** Usefulness, CS relevance, reliability testing, responsible use, documentation, and demonstration

#### Assistant Quality & Usefulness (10 marks)

| Score | Criteria |
|-------|----------|
| **9-10** | Highly useful for a defined CS career goal; supports realistic practice and asks for evidence |
| **7-8** | Useful and relevant, with minor generic or unclear instructions |
| **5-6** | Somewhat useful but not consistently tailored or bounded |
| **3-4** | Minimal customization; limited usefulness; generic prompts |
| **0-2** | Not customized or not useful |

**Evaluation Checklist:**
- [ ] Addresses specific career goal?
- [ ] Personalized to student's background?
- [ ] Covers project descriptions, CS role exploration, or technical interview practice?
- [ ] Prompts are detailed and thoughtful?
- [ ] Would student actually use this?
- [ ] Shows clear understanding of their career path?

---

#### Customization & Personalization (8 marks)

| Score | Criteria |
|-------|----------|
| **7-8** | Highly tailored to individual; specific skills, goals, background; unique approach |
| **5-6** | Good customization; mostly tailored; some generic elements |
| **3-4** | Some customization; partially tailored; mostly generic |
| **0-2** | Generic, not customized to individual |

**Customization Elements:**
- [ ] Specific job roles targeted?
- [ ] Personal skills and background included?
- [ ] Uses actual role descriptions or stated interests rather than invented company claims?
- [ ] Timeline and goals are personal?
- [ ] Addresses individual's specific challenges?
- [ ] Recommendations are relevant to them?

---

#### Documentation (4 marks)

| Score | Criteria |
|-------|----------|
| **3-4** | Clear documentation; explains purpose, how it works, improvements, lessons learned |
| **2** | Decent documentation; covers most areas |
| **0-1** | Minimal documentation |

**Documentation Should Include:**
- [ ] Purpose and problem solved
- [ ] How the assistant works
- [ ] Key capabilities
- [ ] Limitations
- [ ] How to improve it
- [ ] Lessons learned

---

#### Demonstration (3 marks)

| Score | Criteria |
|-------|----------|
| **3** | Clear, effective demo; shows key features; confident explanation |
| **2** | Decent demo; shows some features; mostly confident |
| **1** | Weak demo; limited features shown; low confidence |

#### Testing and Responsible Use (15 marks)

| Score | Criteria |
|-------|----------|
| **13-15** | Tests at least five realistic and failure-oriented cases; catches unsupported claims; revises instructions; protects private data |
| **10-12** | Tests multiple cases and makes a useful revision; privacy and limitations are clear |
| **6-9** | Some testing, but misses important failure cases or responsible-use limits |
| **1-5** | Minimal testing; little evidence of verification |
| **0** | No tests or unsafe handling of sensitive information |

**Test checklist:**
- [ ] Does not invent projects, skills, credentials, or job requirements?
- [ ] Asks one interview question at a time and waits for the response?
- [ ] Distinguishes supplied evidence from general suggestions?
- [ ] Gives feedback that can be checked against course material?
- [ ] Includes privacy limits and honest limitations?

---

### 5. FINAL PARTICIPATION & DEMONSTRATION (10 Marks)

**Evaluating:** Overall engagement, presentation skills, knowledge demonstration

#### Participation & Engagement (5 marks)

| Score | Criteria |
|-------|----------|
| **4-5** | Actively engaged throughout workshop; asks questions; helps peers; attends all sessions |
| **3** | Generally engaged; participates in discussions; mostly attentive |
| **2** | Moderate engagement; participates sometimes; some distractions |
| **1** | Low engagement; minimal participation; often distracted |
| **0** | Not engaged; absent |

**Participation Indicators:**
- [ ] Asks thoughtful questions?
- [ ] Participates in group discussions?
- [ ] Helps other students?
- [ ] Shows curiosity and enthusiasm?
- [ ] Comes prepared to classes?
- [ ] Attends all 5 days?

---

#### Presentation Skills (5 marks)

| Score | Criteria |
|-------|----------|
| **4-5** | Clear, confident presentation; good pacing; engages audience; handles questions well |
| **3** | Decent presentation; mostly clear; adequate pacing |
| **2** | Adequate presentation; some clarity issues; rushed or slow |
| **1** | Poor presentation; unclear; doesn't handle questions |
| **0** | Didn't present |

**Presentation Evaluation:**
- [ ] Clear voice, good volume?
- [ ] Appropriate pacing (not too fast/slow)?
- [ ] Makes eye contact with audience?
- [ ] Organized thoughts logically?
- [ ] Handles technical difficulties?
- [ ] Answers questions directly?
- [ ] Shows enthusiasm?

## 🎯 Holistic Grading Guide

### 90-100: Excellent
- Outstanding projects with clear understanding
- High-quality work demonstrating mastery
- Strong communication of concepts
- Creative applications of tools
- Helps peers and contributes to learning environment

### 80-89: Good
- Well-executed projects
- Solid understanding of concepts
- Good work quality with minor issues
- Clear communication
- Participates actively

### 70-79: Satisfactory
- Completed projects adequately
- Basic understanding demonstrated
- Work has some issues but is acceptable
- Can explain concepts
- Participated in activities

### 60-69: Needs Improvement
- Projects completed but with significant gaps
- Limited understanding shown
- Work has multiple issues
- Difficulty explaining concepts
- Minimal participation

### Below 60: Unsatisfactory
- Incomplete projects
- Poor understanding shown
- Significant issues with work quality
- Cannot explain concepts
- Did not participate adequately

## 📋 Rubric for Self-Assessment

**Students can use this to evaluate their own work:**

### Project Quality Self-Check

**Functionality (Do my projects actually work?)**
- [ ] Project successfully accomplishes its goal
- [ ] AI/tool responds appropriately to queries
- [ ] User can understand and use it
- [ ] It solves a real problem

**Customization (Is it personalized to me/my context?)**
- [ ] Tailored to my specific needs
- [ ] Reflects my unique situation
- [ ] Personal touches beyond basic template
- [ ] Would be useful to me or others

**Documentation (Did I explain it clearly?)**
- [ ] Purpose is clear
- [ ] How it works is explained
- [ ] Screenshots/examples provided
- [ ] Limitations acknowledged

**Demonstration (Can I present it well?)**
- [ ] I can explain my project confidently
- [ ] I can answer questions about it
- [ ] Demo runs smoothly
- [ ] I sound knowledgeable

### Learning Self-Check

**Knowledge**
- [ ] I understand what GenAI is
- [ ] I know difference between AI, ML, GenAI
- [ ] I understand hallucinations and limitations
- [ ] I can write effective prompts

**Skills**
- [ ] I can use 3+ AI tools
- [ ] I can build simple AI applications
- [ ] I can troubleshoot when AI gives wrong answers
- [ ] I can automate simple workflows

**Mindset**
- [ ] I'm excited about AI possibilities
- [ ] I understand both benefits and risks
- [ ] I'm curious to learn more
- [ ] I can use AI ethically

## 💡 Feedback Template for Instructors

**Give constructive feedback to students:**

```
STUDENT: [Name]
PROJECT: [Project Name]

STRENGTHS:
- [What they did well]
- [Specific good example]
- [Skill they demonstrated]

AREAS FOR IMPROVEMENT:
- [What could be better]
- [Specific suggestion]
- [How to improve]

QUESTIONS FOR REFLECTION:
- [Question to deepen their thinking]
- [Challenge for next level]

GRADE: [Mark]/[Total]

COMMENTS:
[Encouraging, specific feedback]
```

## 📊 Class Grade Distribution

**After grading all students, analyze:**

```
A (90-100): ___ students (_%) - Excellent work
B (80-89): ___ students (_%) - Good work
C (70-79): ___ students (_%) - Satisfactory
D (60-69): ___ students (_%) - Needs improvement
F (<60): ___ students (_%) - Unsatisfactory

Average: ___
Median: ___
Range: ___
```

**If too many low grades:**
- Provide extra support sessions
- Adjust project difficulty
- Offer revision opportunities

**If high variance:**
- Some students need more challenge
- Some students need more support
- Consider flexible pacing

---

## 🔍 Quality Assurance Checklist

**For Instructors - Ensure Fair Assessment:**

- [ ] All students evaluated using same rubric
- [ ] Rubric criteria are clear and objective
- [ ] Grades reflect actual demonstrated learning
- [ ] Students understand evaluation criteria beforehand
- [ ] Feedback is constructive and specific
- [ ] Assessment aligns with learning objectives
- [ ] Multiple measures used (not just one project)
- [ ] Student input/self-assessment considered
- [ ] Grade distribution is reasonable
- [ ] Documentation of grades is maintained

---

**End of Assessment Rubric**

**Remember: Assessment should support learning, not just measure it.**

**Provide feedback that helps students improve and understand their strengths!**
